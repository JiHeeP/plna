# 인사이트 출력 방식 점검

## 현재 상태 요약
- 현재 코드베이스에는 LLM(OpenAI/Claude 등)을 호출하는 API 라우트, 프롬프트 템플릿, 모델 응답 후처리 로직이 없습니다.
- `goals` 화면의 값은 DB 집계(마일스톤/수치 로그/대화 주제 개수)를 그대로 계산해 퍼센트로 보여줍니다.
- 즉, 현재는 "AI 기반 의미 추론"이 아니라 "진척도 시각화"에 가깝습니다.

## 왜 "의미 있는 결론"이 약한가
1. 인과/맥락 추론 단계 부재
   - 데이터 수집 → 집계 → UI 출력은 있지만, 원인-대안-우선순위 생성 단계가 없습니다.
2. 시간축 비교의 질적 해석 부재
   - 수치 변화는 보여주지만, 변화 이유/행동 제안을 자동 생성하지 않습니다.
3. 인사이트 품질 기준 미정
   - "좋은 인사이트"를 판별할 기준(정확성, 실행가능성, 개인 맥락 반영)이 정의되지 않았습니다.

## 의미 있는 AI 인사이트를 위해 사용자(또는 시스템)가 추가로 제공할 것

### 1) 최소 입력 데이터 스키마
- 목표 컨텍스트: 목표명, 기한, 현재 우선순위, 제약(시간/돈/에너지)
- 주간 로그: 한 일, 못한 일, 방해 요인, 감정 에너지(1~5), 집중 시간
- 결과 지표: 핵심 KPI 1~3개(예: 완료율, 학습시간, 수익)

### 2) 인사이트 출력 포맷 고정
- 사실 요약(What happened)
- 원인 가설(Why)
- 다음 행동 3개(What next, 난이도/기대효과 포함)
- 리스크 1~2개 및 대응

### 3) 품질 검증 루프
- 각 인사이트에 대해 "도움됨/불필요" 피드백 수집
- 다음 생성 시 피드백을 프롬프트 컨텍스트에 반영
- 2주 단위로 행동 이행률과 성과 개선률을 체크

## 바로 실행 가능한 다음 단계 (1주)
1. AI 인사이트 API 추가 (`/api/insights`)
2. 프롬프트 템플릿에 위 출력 포맷 강제
3. 입력 누락 시 "결론 보류 + 추가 질문" 반환
4. UI에 "근거 데이터"와 "신뢰도" 배지 표시
